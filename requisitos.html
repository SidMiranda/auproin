Este material descreve como o ambiente vai funcionar na rede da empresa e o que a equipe de TI precisa preparar. Tudo roda localmente (on-premise). Os dados de produção nunca saem da rede interna.

Parte 1

Fluxo dos dados, do sensor ao dashboard

O sistema de aquisição grava arquivos .dat numa pasta. Uma estação Windows converte esses arquivos para .txt em outra pasta. O servidor Linux lê os .txt, grava no banco e publica os dashboards na rede interna.

Infraestrutura, acesso remoto e backup

Nenhuma porta é aberta para a internet. O suporte acessa o servidor por um túnel que só faz conexão de saída. Onde a VM roda e para onde vai a cópia do backup ficam a critério do TI.

Rede e acessos a liberar

  • Saída HTTPS na porta 443 para *.cloudflare.com e *.argotunnel.com. Nenhuma porta de entrada.
  • Usuário Linux para o suporte, com sudo e no grupo docker. SSH pelo túnel (Cloudflare Access) ou pela VPN da empresa.
  • Servidor acessível na rede interna pelas portas 80 e 443, com um nome interno e certificado.
  • Usuário de rede com somente leitura na pasta .txt, para montagem no Linux via SMB/CIFS.
  • Estação Windows com leitura na pasta .dat, escrita na pasta .txt e acesso remoto interno para manutenção.
  • Saída para atualizações: Docker Hub e repositórios do Ubuntu (apt). SMTP interno, se houver envio de e-mail.
  • Banco de dados (5432) não fica exposto na rede.

Decisões que ficam com o TI

  • Hipervisor: VMware ou Hyper-V. Também pode ser servidor físico.
  • Volumes: NAS, storage ou servidor de arquivos para as pastas .dat e .txt.
  • Backup secundário: o servidor já gera backup diário local às 03h. A cópia para NAS, storage ou fita é opcional.
  • Atualizações: aplicadas pelo túnel ou em janela combinada com o TI.
  • Protocolo dos volumes: SMB/CIFS sugerido. Outro protocolo pode ser combinado.
